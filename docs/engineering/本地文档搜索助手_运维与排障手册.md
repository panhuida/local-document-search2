# 本地文档搜索助手：运维与排障手册

## 1. 文档目的

本文档面向日常使用、联调和问题排查，沉淀本项目当前版本的：

- 常用运维命令
- 推荐诊断顺序
- 常见异常与处理方案
- 当前实现边界与注意事项

本文档重点是“怎么定位、怎么处理”，不是功能介绍。


## 2. 快速诊断顺序

遇到问题时，建议按下面顺序排查。

### 2.1 先确认环境是否正常

```powershell
uv sync
uv run python doc-cli.py db init
uv run python run.py
```

如果只是验证 CLI 链路：

```powershell
uv run python doc-cli.py search "测试"
```

### 2.2 再确认基础质量检查是否通过

```powershell
uv run ruff format .
uv run ruff check .
uv run pyright
uv run pytest
```

如果这里已经失败，优先修工程问题，不要先怀疑业务逻辑。

### 2.3 最后用真实目录做 smoke test

例如：

```powershell
uv run python doc-cli.py index "D:\documents\历史" --force --quiet
uv run python doc-cli.py search "历史"
uv run python doc-cli.py errors list
```

## 5. 常见问题与处理方案

### 5.1 `no such table: ingest_state`

典型现象：

- Web 索引页提交目录后直接报错
- 异常类似：
  - `sqlite3.OperationalError: no such table: ingest_state`

原因：

- 数据库未初始化，或者初始化不完整

处理建议：

```powershell
uv run python doc-cli.py db init
```

然后重启 Web：

```powershell
uv run python run.py
```

当前版本说明：

- 应用启动时会做轻量初始化
- 但如果数据库文件损坏或目录切换，仍建议显式执行一次 `db init`

### 5.2 `database is locked`

典型现象：

- CLI 索引时报 SQLite 被锁
- 多开 Web / CLI 后偶发失败

原因：

- 残留 Python 进程仍在占用数据库
- 同时发起多个索引或写入任务

当前已实现的缓解措施：

- SQLite 已启用 `WAL`
- SQLite 已配置 `busy_timeout`

但如果仍出现锁冲突，建议直接排查残留进程。

查看相关进程：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -match 'python|pwsh' -and $_.CommandLine -match 'local-document-search|doc-cli.py|run.py' } |
  Select-Object ProcessId, Name, CommandLine | Format-List
```

必要时结束残留进程：

```powershell
Stop-Process -Id <PID>
```

注意：

- 不要在一个数据库文件上同时起多个重索引任务

### 5.3 `数据库中不应出现不带时区的时间字符串`

典型现象：

- 强制重新索引或读取旧记录时报错
- 报错类似：
  - `数据库中不应出现不带时区的时间字符串，请重建或重新索引旧数据。`

原因：

- 旧版数据库里残留了 naive 时间字符串
- 当前系统已经切换到 aware UTC 规则，不再兼容旧格式

推荐处理方式：

方案一：对相关目录执行强制重新索引

```powershell
uv run python doc-cli.py index "D:\documents\历史" --force --quiet
```

方案二：如果旧数据范围不清晰，直接重建数据库

```powershell
uv run python doc-cli.py db init
```

注意：

- 当前策略是不兼容旧 naive 时间，而不是运行时偷偷兜底

### 5.4 Web 索引页面一直转圈，看不到进度

典型现象：

- 点击“开始索引”后浏览器一直等待
- 不知道当前索引到哪里

当前版本状态：

- 已改为后台任务模式
- 页面会轮询显示任务状态、当前文件、计数和结果

如果仍然看不到任务：

- 先确认服务是否是最新代码版本
- 再确认浏览器是否仍停留在旧缓存页面
- 最后确认没有重启 Flask 进程

注意：

- 当前索引任务状态是“进程内内存态”
- 如果重启 Web 进程，运行中的任务状态不会保留

### 5.5 切到别的页面再回“文档索引”，任务状态不见了

当前版本状态：

- `/index` 会优先显示当前活跃任务
- 没有活跃任务时显示最近一次任务

如果任务仍然消失，优先怀疑：

- 服务进程被重启
- 浏览器打开了另一个旧实例

### 5.6 MarkItDown 处理大文件卡住或超时

典型现象：

- 某些 PDF / PPTX / DOCX / XLSX 索引特别慢
- 最终进入错误记录
- 错误提示为超时

当前规则：

- `MARKITDOWN_TIMEOUT_SECONDS` 可配置
- 超时会记为 `failed`
- 超时文件进入错误记录，便于后续重试

配置示例：

```dotenv
MARKITDOWN_TIMEOUT_SECONDS=120
```

修改后建议：

1. 重启应用
2. 重新重试错误记录

```powershell
uv run python doc-cli.py errors retry
```

### 5.7 `.assets` 目录里的图片没有被索引

这是当前默认行为，不是 bug。

默认规则：

- 名称包含 `.assets` 的目录整棵子树跳过

原因：

- 这类目录通常是 Markdown 笔记图片目录，索引价值低、噪声高

如果确实要索引，显式关闭默认排除：

```dotenv
EXCLUDED_DIR_KEYWORDS=
```

然后重新启动并重索引。

### 5.8 “打开所在目录”打开了错误目录或焦点不对

当前 Windows 实现使用：

- `explorer.exe /select, 文件路径`

这样做的目标是：

- 打开正确目录
- 直接定位文件

注意：

- 资源管理器是否抢到前台焦点，不完全由应用控制
- 这是 Windows 窗口管理边界，不是业务代码能 100% 保证的事情

如果出现目录不对，优先检查：

- 数据库里该文档记录的 `file_path` 是否正确
- 文件是否已移动但未重新索引

推荐处理：

```powershell
uv run python doc-cli.py index "D:\documents\历史" --force --quiet
```

### 5.9 “预览”页和“打开文件”行为不符合预期

当前推荐交互：

- “预览”：新标签打开
- “打开文件”：异步触发系统打开，不刷新当前页面
- “打开所在目录”：异步触发系统打开，不刷新当前页面

如果行为异常，优先检查：

- 模板是否回退到了旧版实现
- 浏览器缓存是否未刷新
- 当前页面是否仍加载旧 JS

### 5.10 Markdown 表格看起来没渲染

当前版本已经切换到 `markdown-it-py`，并补了表格样式。

如果表格仍然不对，优先检查两点：

- Markdown 语法本身是否正确
- 页面是否加载了最新的 `base.html` 样式

注意：

- Markdown 里的原生 HTML 当前默认会被转义，而不是直接注入页面

### 5.11 搜索结果不符合预期

建议按这个顺序排查：

1. 先确认文档是否已成功索引
2. 再确认该文件没有进入错误记录
3. 再确认关键词是否真的存在于 `content_markdown`
4. 最后再看搜索后端行为

快速定位命令：

```powershell
uv run python doc-cli.py search "关键词" --limit 20
uv run python doc-cli.py errors list
```

## 8. 当前实现边界

### 8.1 已知边界

- 索引任务状态不跨服务重启持久化
- 浏览器无法提供真正可供服务端使用的本机目录句柄
- 浏览器无法强制系统窗口抢前台焦点
- SQLite 适合本地 v1，但不是最终形态的高阶中文搜索方案

### 8.2 处理边界问题的原则

- 先确认是不是产品边界，而不是代码 bug
- 对边界问题给出明确说明，不要做“看起来可用”的假实现
- 如果需求超出浏览器本身能力，应及时评估桌面壳层或辅助进程方案
